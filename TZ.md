# Техническое задание — EventSphere

Веб-приложение для поиска и организации городских событий Бишкека: хакатоны, клубы, воркшопы, поездки, спорт. Документ описывает реализованный MVP и границы, за которые он не выходит.

- Версия: 1.0, 29.10.2026
- Прод: https://eventsphere-self.vercel.app
- Код: https://github.com/AmanTugolbekov/SkillabAi

---

## 1. Назначение и проблема

Афиши событий в Бишкеке живут в Instagram и Telegram-каналах: событие находится случайно, часто уже после дедлайна, а запись идёт в личку организатора. С другой стороны, организатор-любитель не публикует событие потому, что на оформление анонса, сбор заявок и ответы на одни и те же вопросы уходит больше сил, чем на само событие.

EventSphere решает две связанные задачи:

1. участник находит событие по смыслу запроса, а не перебором фильтров, и записывается в один тап;
2. организатор публикует событие из одного текстового сообщения — остальное раскладывает по полям AI.

### 1.1 Роли

| Роль | Как получает | Что может |
| --- | --- | --- |
| Участник | регистрация по почте или через Google | смотреть афишу, искать, записываться |
| Детский профиль | создаётся родителем в профиле | не логинится; записывается только родителем |
| Организатор | участник нажимает «стать организатором» | публиковать события, видеть участников |
| Верифицированный организатор | прошёл KYC, подтверждён модератором | то же + значок доверия в карточке |
| Модератор | только служебный аккаунт (`is_admin = 1`) | проверять и подтверждать заявки KYC |

## 2. Функциональные требования

### 2.1 Регистрация и доступ

- **F-1.** Регистрация по почте и паролю. Пароль хранится как scrypt-хеш с индивидуальной солью; открытый пароль не хранится и не логируется.
- **F-2.** Вход через Google OAuth 2.0 (authorization code flow). Аккаунт связывается по `sub` из `id_token`. Если почта Google совпадает с существующим аккаунтом — вход в него, без дубликата.
- **F-3.** Сессия — подписанная HMAC-SHA256 cookie `es_session` вида `<user_id>.<expires>.<signature>`, `httpOnly`, `sameSite=lax`, срок 30 дней. Подпись проверяется на каждом запросе; истёкшая или подделанная cookie трактуется как отсутствие сессии.
- **F-4.** Онбординг: год рождения. Возраст участника определяет, какие события ему доступны, поэтому поле обязательное.
- **F-5.** Страницы, требующие входа, редиректят на `/login?next=<путь>` и возвращают пользователя туда, откуда он пришёл.
- **F-6.** Экран модерации доступен только аккаунту с `is_admin = 1`. Для всех остальных он отвечает 404 и не показывается в навигации — не скрытая кнопка, а проверка на сервере.

### 2.2 Афиша и карточка события

- **F-7.** Лента событий: сначала избранные, внутри — по дате начала. Сверху крупная карточка события-героя.
- **F-8.** Фильтры: поиск по тексту, категория, район, цена (бесплатные или до суммы), возраст, только верифицированные организаторы, дата. Полоса дат — 21 день вперёд.
- **F-9.** Сетка карточек — две в ряд. Карточка содержит фотографию места, дату, заголовок, место проведения, цену и значок срочности («сегодня», «мест мало», «до дедлайна N дней»).
- **F-10.** Карточка события: программа по пунктам, требования к участнику, что входит в участие, место, цена, возрастные ограничения, организатор с рейтингом и статусом верификации, число занятых мест.
- **F-11.** Все изображения — реальные фотографии места или события. Эмодзи и иконки-заглушки в контенте не используются.

### 2.3 Запись на событие

- **F-12.** Запись одним действием для вошедшего пользователя. Повторная запись на то же событие тем же участником невозможна (ограничение на уровне БД).
- **F-13.** При лимите мест запись закрывается по достижении лимита. Занятыми считаются только подтверждённые записи.
- **F-14.** Запись после дедлайна невозможна.
- **F-15.** Возрастной фильтр: если возраст участника вне диапазона события, запись не предлагается.
- **F-16.** Платная запись к неверифицированному организатору закрыта: пока KYC не подтверждён, он публикует только бесплатные события.
- **F-17.** Запись ребёнка, созданная родителем, подтверждается сразу. Заявка, инициированная с детского профиля, попадает в статус `awaiting_parent` и становится `confirmed` только после подтверждения родителем на отдельном экране.
- **F-18.** Экран «мои события»: предстоящие записи, записи детей, ожидающие подтверждения.

### 2.4 Организатор

- **F-19.** Любой участник становится организатором без модерации — иначе исчезает смысл платформы для любителей.
- **F-20.** Публикация события из свободного текста: организатор вставляет сообщение, как написал бы его в чат, AI раскладывает текст по полям, все поля остаются доступны для правки до публикации.
- **F-21.** Голосовая диктовка анонса вместо набора текста.
- **F-22.** Список своих событий со статистикой: записались, ожидают подтверждения, осталось мест.
- **F-23.** Список участников своего события.
- **F-24.** Заявка на верификацию: тип документа, последние 4 цифры, ФИО. Полный номер документа не передаётся и не хранится.

### 2.5 Модерация

- **F-25.** Экран заявок KYC со статусами `pending`, `verified`, `rejected`.
- **F-26.** Подтверждение или отказ с комментарием; у организатора статус и комментарий видны в его профиле.

### 2.6 AI-функции

- **F-27.** Поиск на естественном языке. Запрос пользователя («что есть для ребёнка 10 лет в субботу») превращается в структурированный набор условий: категории, районы, цена, возраст, диапазон дат, ключевые слова.
- **F-28.** Разобранный запрос показывается пользователю чипами — видно, во что AI превратил фразу, и почему выдача такая.
- **F-29.** Если под условия ничего не нашлось, часть условий снимается, и пользователю прямо сообщается, что именно было ослаблено.
- **F-30.** Структурирование анонса: из свободного текста заполняются заголовок, описание, категория, формат, район, место, цена, даты начала, окончания и дедлайна, возрастные границы, лимит мест, программа, требования, что включено, теги.
- **F-31.** Голосовой ввод в поиске и при создании события — Web Speech API браузера, `ru-RU`. Распознавание непрерывное, пауза в речи запись не обрывает. Аудио не передаётся на наш сервер и не хранится. Там, где API недоступен (Firefox), кнопка не отображается, ввод с клавиатуры работает как обычно.
- **F-32.** Распознанный текст подчищается по словарю доменных терминов («ай ти» → IT, «хака тон» → хакатон, «иссык куль» → Иссык-Куль).

## 3. AI-слой

### 3.1 Приоритет провайдеров

Один интерфейс, три реализации, выбор на запуске по доступным ключам:

1. **Claude** (`@anthropic-ai/sdk`) — если задан `ANTHROPIC_API_KEY`;
2. **Gemini** (`gemini-3.5-flash`, structured output через `responseSchema`) — если задан `GEMINI_API_KEY`;
3. **Эвристика** — правила на регулярных выражениях, без сети.

- **F-33.** Отсутствие ключей не ломает приложение: поиск и публикация работают на эвристике, интерфейс честно подписывает, какой движок разобрал запрос («Gemini разобрал как», «разобрано как»).
- **F-34.** Ответ любого провайдера валидируется zod-схемой (`EventDraftSchema`, `SearchIntentSchema`). Невалидный ответ не доходит до БД: запрос уходит на следующий уровень приоритета.
- **F-35.** Модель не получает доступа к БД и не пишет в неё. Её выход — только набор условий фильтрации и черновик полей формы, который подтверждает человек.

### 3.2 Выбор модели

`gemini-3.5-flash` выбран замером на нашем же наборе запросов: 4.7 с на структурирование анонса при лучшем качестве разбора среди протестированных. `gemini-3.8-flash` под нагрузкой отдавал 503 и уходил за 60 с, а с `thinkingBudget: 0` качество разбора падало до неприемлемого.

## 4. Архитектура

| Слой | Решение |
| --- | --- |
| Фронтенд и бэкенд | Next.js 16 (App Router), React 19, TypeScript, серверные компоненты и server actions |
| Стили | Tailwind CSS 3.4, токены на CSS-переменных |
| База | Turso (libSQL), SQL-схема в `lib/schema.sql` |
| Хостинг | Vercel, регион функций `arn1` (Стокгольм) |
| Аутентификация | своя, на `node:crypto` (scrypt + HMAC), без внешних библиотек |
| AI | Anthropic SDK / Gemini REST / локальная эвристика |
| Распознавание речи | Web Speech API браузера |

### 4.1 Структура кода

```
app/            маршруты: афиша, карточка, поиск, профиль, организатор, модерация
  api/          поиск, структурирование анонса, Google OAuth
components/     карточка события, навигация, формы, голосовой ввод
lib/
  db.ts         клиент libSQL, единая точка доступа
  queries.ts    все SQL-запросы приложения
  auth.ts       хеширование пароля, сессия, Google OAuth
  session.ts    текущий пользователь, requireUser, requireAdmin
  ai.ts         выбор провайдера
  ai-gemini.ts  Gemini со structured output
  ai-fallback.ts эвристический разбор
  ai-shape.ts   zod-схемы ответов AI
  photo.ts      сопоставление события и фотографии места
  speech.ts     подчистка распознанной речи
scripts/
  seed.mjs           демонстрационный набор данных
  push-to-turso.mjs  перенос схемы и данных в облако
```

### 4.2 Модель данных

- `users` — участники, детские профили (`parent_id`), флаг `is_admin`;
- `organizers` — профиль организатора и состояние KYC, 1:1 с `users`;
- `events` — событие; структурированные блоки (программа, требования, что включено, теги) хранятся JSON-массивами в текстовых полях;
- `registrations` — запись со статусом, с разделением «кто идёт» (`attendee_id`) и «кто записал» (`booked_by_id`), уникальность по паре событие+участник.

Индексы: уникальные частичные по `email` и `google_sub` (несколько NULL допустимы — детские профили без почты), по дате начала и категории события, по участнику в записях.

## 5. Нефункциональные требования

- **N-1. Мобильный веб в первую очередь.** Вёрстка рассчитана на экран от 375 px, нижняя навигация, без горизонтальной прокрутки.
- **N-2. Светлая и тёмная темы.** Выбор хранится в cookie и применяется на сервере — переключение без вспышки чужой темы при загрузке.
- **N-3. Скорость.** Достигнуто на проде: TTFB афиши 0.54 с, экран AI-поиска 0.39 с. База и функции размещены в одном регионе; расхождение регионов обходилось приложению примерно в 1 с на запрос.
- **N-4. Вес изображений.** Обложки сжаты до 1200 px по ширине, прогрессивный JPEG; набор обложек — 3.4 МБ вместо исходных 11.6 МБ.
- **N-5. Безопасность.** Пароли — scrypt с солью; cookie сессии подписана и `httpOnly`; доступ к модерации проверяется на сервере; полные номера документов не хранятся; ключи только в переменных окружения.
- **N-6. Отказоустойчивость AI.** Недоступность провайдера или невалидный ответ не приводят к ошибке у пользователя — работает следующий уровень приоритета.
- **N-7. Язык интерфейса** — русский. Числительные согласуются по правилам русского языка («41 день», не «41 дней»).

### 5.1 Переменные окружения

| Переменная | Назначение | Обязательна |
| --- | --- | --- |
| `TURSO_DATABASE_URL` | облачная база; без неё берётся локальный файл | на проде да |
| `TURSO_AUTH_TOKEN` | токен доступа к базе | вместе с URL |
| `SESSION_SECRET` | ключ подписи cookie сессии | да |
| `GEMINI_API_KEY` | AI-разбор через Gemini | нет |
| `ANTHROPIC_API_KEY` | AI-разбор через Claude | нет |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | вход через Google | нет |

Приложение запускается при любом подмножестве необязательных ключей: без них отключаются соответствующие функции, а не приложение.

## 6. Границы MVP

Сознательно не реализовано:

- **Платежи.** Цена события — информационное поле, оплата идёт вне платформы.
- **Отмена своей записи и редактирование опубликованного события** — первое в очереди на доработку.
- **Отзывы и рейтинг.** Рейтинг организатора заполнен демонстрационными данными, механизм отзывов не реализован.
- **Уведомления** (push, почта, Telegram).
- **Чат** между участником и организатором.
- **Проверка подлинности документов KYC.** Модератор решает по заявке; автоматической верификации нет.
- **Несколько городов.** Поле `city` в схеме есть, интерфейс работает с Бишкеком.
- **Автоматическое скрытие прошедших событий.** Лента отдаёт всё, что есть в базе; в демонстрационном наборе все события будущие, поэтому в глаза не бросается.
- **Распознавание речи на кыргызском** — зависит от движка браузера.

## 7. Критерии приёмки

Проверяется на проде, в Chrome или Safari, с телефона:

1. Регистрация нового аккаунта по почте проходит, после входа открывается афиша; повторный вход с тем же паролем работает.
2. Вход через Google создаёт аккаунт и не ломает существующий с той же почтой.
3. Запись на событие появляется в «моих событиях», повторная запись на то же событие невозможна, счётчик мест уменьшается.
4. Событие с лимитом мест перестаёт принимать записи по достижении лимита; событие после дедлайна записи не принимает.
5. Запрос «найди бесплатный хакатон для студентов» в AI-поиске возвращает подборку и чипы разбора, соответствующие запросу.
6. Свободный текст анонса (пример — в форме создания) превращается в заполненную форму: заголовок, дата, цена, место, программа.
7. Голосовой ввод в поиске заполняет поле текстом сказанного; пауза в середине фразы запись не обрывает.
8. Экран модерации открывается служебному аккаунту и отвечает 404 обычному.
9. Переключение светлой и тёмной темы не вызывает вспышки чужой темы при перезагрузке.
10. Приложение работает при удалённых AI-ключах: поиск и публикация переходят на эвристику, интерфейс это подписывает.

## 8. Запуск

```bash
npm install
npm run seed
npm run dev
```

Приложение поднимается на http://localhost:3000. Для облачной базы — `npm run db:push` при заданных `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`. Демонстрационные аккаунты и порядок проверки — в [SUBMISSION.md](SUBMISSION.md).
