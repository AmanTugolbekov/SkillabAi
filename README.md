# EventSphere

Единая лента локальных событий Бишкека: хакатоны, клубы, воркшопы, поездки.
Два режима в одном приложении — участник и организатор, — проверка организаторов
по документу и AI на двух участках, где людям реально больно.

## Запуск

```bash
npm install
npm run seed   # создаёт data/eventsphere.db и наполняет демо-данными
npm run dev    # http://localhost:3000
```

Нужен Node 22+: база работает на встроенном модуле `node:sqlite`, без нативных сборок.

### AI

Без ключа приложение работает полностью: разбор текста и поисковых запросов идёт
по встроенным правилам (`lib/ai-fallback.ts`). С ключом те же два вызова уходят в
Claude — менять в коде ничего не нужно:

```bash
echo "ANTHROPIC_API_KEY=sk-ant-..." > .env.local
```

Текущий движок виден в профиле и подписан на самих экранах — ассистент не делает
вид, что он умнее, чем есть.

## Что внутри

**Участник**

- лента с фильтрами: категория, район, цена, возраст, только проверенные организаторы;
- карточка события: программа, требования, что входит, дедлайн, занятые места;
- AI-поиск: запрос обычными словами → фильтры → подборка, с показом того, как
  ассистент понял запрос;
- «Мои записи» и родительский контроль.

**Организатор**

- создание события из сплошного текста: AI раскладывает его на заголовок, программу,
  требования, цену, даты и возраст — поля остаются редактируемыми;
- KYC: заявка с документом, статусы, экран модерации (`/admin`);
- список участников и ожидаемые сборы.

## Два правила, на которых держится доверие

1. **Платный сбор — только после верификации.** Организатор без подтверждённой
   личности не может ни опубликовать платное событие, ни принять на него запись.
2. **Профиль младше 13 лет ведёт родитель.** Если ребёнок записывается сам, заявка
   уходит родителю и место не считается занятым, пока он не подтвердит.

## Внешний вид

Афишная вёрстка: фотография ведёт карточку, под шапкой — полоса дат, категории
чипами. Референсы — ticket.kg и kassir.kg. Эмодзи не используются: у организаторов
и участников кружки с инициалами, у событий — фотографии.

Снимки лежат в `public/events`, все со свободными лицензиями (Openverse,
Викисклад, Unsplash). Авторство и лицензии — в `public/events/CREDITS.md`.

Где удалось найти снимок настоящего места события, стоит именно он:
библиотека им. Баялинова, кинотеатр «Ала-Тоо», Ботанический сад, КТУ,
парк Ататюрка, Иссык-Куль, Чуйская долина, площадь Ала-Тоо. Такие файлы лежат
в `public/events/places`. Остальным событиям подобран тематический кадр.
Соответствие задано в `lib/photo.ts`; событие, созданное организатором,
получает снимок по своей категории.

Карточки идут сеткой в две колонки, как на афишных сайтах.

## Структура

```
app/            экраны и серверные действия
  api/search    запрос на естественном языке → фильтры → события
  api/structure текст анонса → структурированный черновик
lib/
  ai.ts         вызовы Claude, с переключением на фоллбэк
  ai-fallback.ts разбор текста и запросов без ключа
  ai-shape.ts   zod-схемы ответов AI
  queries.ts    все запросы к базе
  schema.sql    схема SQLite
scripts/seed.mjs демо-данные: 26 событий, 6 организаторов, семья с детьми
```

## Чего намеренно нет

Платежей, escrow, подбора команд на хакатон и реальной проверки документов. Это
следующий этап: сейчас в коде есть места, куда они встают, но ставить полурабочую
оплату в прототип вреднее, чем честно обозначить границу.

## Демо за три минуты

1. Лента → AI-поиск → «Языковой клуб в центре до 500 сом».
2. Профиль → «Организатор» → «Создать» → «вставить пример» → «Структурировать с AI».
3. Попытка опубликовать платное событие → блок по верификации → KYC → `/admin` →
   «Подтвердить» → публикация проходит.
4. Профиль → аккаунт «Алина Асанова» (10 лет) → запись на событие → заявка родителю.
5. Профиль → «Тимур Асанов» → «Мои записи» → «Разрешить».
